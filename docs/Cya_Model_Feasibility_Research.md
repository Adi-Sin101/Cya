## Confirmed family capabilities

Google's second-generation model card confirms text/code, audio, images and video share a 768-dimensional space. Its approximate modular counts are 270M text, 440M text+vision, 570M text+audio and 740M full; these are model configurations, not proof that each configuration has a separate Android download. The shared context is 8,192 tokens. Audio uses mono 16 kHz, about 25 tokens/second and approximately 327 seconds when consuming the context alone. The card describes over 100 languages, without guaranteeing Bangla or code-switch quality. MRL supports 768/512/256/128 dimensions; truncate then L2-normalize, and use the same dimension for query and corpus. The card warns against float16 activations; use bfloat16 where supported or float32 for the reference. Text uses task prefixes; media has none. Search uses `task: search result | query: ...` and `title: ... | text: ...`; relatedness has a separate sentence-similarity prefix. These are model requirements, not proof that a runtime automatically applies them. [Official model card](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2?hl=en).

The official Python example directly embeds an audio input and compares it with textual descriptions; no speech recognition intervenes. Its displayed actual counts are 744,371,488 full parameters and 576,613,664 with vision disabled. It accepts local audio paths or waveforms and resamples audio. Python selective loading is established; Android behavior must be checked separately. The tutorial also demonstrates image/video ingestion, configurable frame sampling, and interleaved media. Its default video processing samples one frame/second; the example exposes uniform/truncate overflow policies. The demonstration's URL-fetching code must not be copied into Cya!'s offline runtime. SentenceTransformers plus Transformers is a useful desktop correctness reference, not an Android deployment strategy. Exact working Python package versions remain to be pinned in the POC. [Official multimodal tutorial](https://ai.google.dev/gemma/docs/embeddinggemma/multimodal-embeddinggemma-with-sentence-transformers).

No standalone text+audio `.litertlm` artifact was listed by the official task guide. Start from the generic 740M artifact with vision inactive; demonstrate that the selected runtime actually avoids its allocation. The checked generic-model repositories list hardware-specific Qualcomm QCS8275 and SM8550/8650/8750/8850 bundles, not an A52-specific compiled NPU artifact. Never treat a newer Qualcomm bundle as interchangeable with an older phone; CPU is the initial portability baseline and GPU requires physical-device validation.

## Runtime evidence and a concrete compatibility blocker

The Android UniversalEmbedder documentation names `com.google.mediapipe:tasks-retrieval`, exposes `embedText`, `embedAudio(AudioData)` and multimodal ingestion, and documents explicit cleanup. It directly depends on LiteRT-LM. It uses `latest.release` in its example; Cya! must pin a tested version instead. [Android guide](https://developers.google.com/edge/mediapipe/solutions/retrieval/universal_embedder/android).

The task overview explicitly names EmbeddingGemma V2 and describes a local LiteRT-LM EmbeddingEngine wrapper with audio buffers, file descriptors, acceleration and normalization controls. Its generic activation menu includes float16 while the model card warns against that precision; generic options do not override model-specific safety. Its license wording also differs from the model card, discussed below. [UniversalEmbedder overview](https://developers.google.com/edge/mediapipe/solutions/retrieval/universal_embedder).

Google Maven metadata currently publishes `tasks-retrieval:1.1.1` (updated 14 October). Its POM depends on **`litertlm-android:0.17.0-alpha1`**, while the current LiteRT-LM release explicitly announces the new embedding support in **v0.18.0**. Direct Android `litertlm-android:0.18.0` is published. This is an unresolved version-pair compatibility risk, not proof the wrapper fails. [Retrieval metadata](https://dl.google.com/dl/android/maven2/com/google/mediapipe/tasks-retrieval/maven-metadata.xml), [exact 1.1.1 POM](https://dl.google.com/dl/android/maven2/com/google/mediapipe/tasks-retrieval/1.1.1/tasks-retrieval-1.1.1.pom), [LiteRT-LM metadata](https://dl.google.com/dl/android/maven2/com/google/ai/edge/litertlm/litertlm-android/maven-metadata.xml).

v0.18.0's release notes identify Kotlin, Python, C++, Swift and Web embedding APIs. The tagged Kotlin `EmbeddingEngine` source has initialization, synchronous/asynchronous embedding, dimensions/normalization options and `close()`, calling JNI. **Recommended first POC:** direct Kotlin LiteRT-LM 0.18.0, generic full artifact, CPU first, no vision; compare a MediaPipe wrapper only after verifying its resolved runtime and API compatibility. No Flutter package should be assumed to expose new audio embedding APIs just because the engine has Kotlin support. [Release](https://github.com/google-ai-edge/LiteRT-LM/releases/tag/v0.18.0), [tagged Kotlin source](https://raw.githubusercontent.com/google-ai-edge/LiteRT-LM/v0.18.0/kotlin/java/com/google/ai/edge/litertlm/EmbeddingEngine.kt).

Android minimum API, AAR ABI contents/size, final native dependency conflicts, page-size compliance, GPU drivers and capture/process isolation remain **unverified**. The POC must compile a minimal release harness for the target's actual API/ABI and pin Gradle dependency resolution. No app refactor is justified before this proof.

The official LiteRT-LM embedding page is accessible through an HTTP read even though the browser reader timed out. Its Kotlin example takes encoded WAV bytes through `InputData.Audio(File(...).readBytes())`; this is distinct from MediaPipe's segmented `AudioData`. Exact accepted codec/container matrix, sample-rate conversion, channel downmix, segment duration, overlap and streamed pooling remain untested for the pinned Android runtime. Prefer a deterministic decoded mono 16 kHz PCM reference; preserve the original recording and derive bounded buffers with timestamps instead of assuming arbitrary AAC/MP4 bytes work. WAV example support does not prove every phone recording format. [LiteRT-LM embedding guide](https://developers.google.com/edge/litert-lm/embedding_models).

**Prompt conflict:** that runtime guide gives document `task: search result | text:` and query `task: search query | text:`, while the main model card gives query `task: search result | query:` and document `title: none | text:`. Its similarity instruction likewise must be compared with the checkpoint's named task. Pin the artifact-specific prompt policy and preserve it in embedding metadata; test both documented conventions against the Python reference and held-out ranking before choosing. Do not double-prefix, normalize away original source text, or compare vectors produced under mismatched policies. This is an evidence-backed ambiguity requiring a compatibility experiment, not permission to invent a prefix. [Runtime prompt table](https://developers.google.com/edge/litert-lm/embedding_models).

The launch blog distinguishes forthcoming ML Kit service integration from currently available bundles and cross-platform APIs. Automatic model updates/service lifecycle do not fit Cya!'s strict local-import requirement without further evidence. Prefer app-owned model files and explicit versioning. [Google AI Edge launch post](https://developers.googleblog.com/google-ai-edge-with-embeddinggemma-2/).

## License and local packaging

Base and LiteRT model metadata declare Apache-2.0. The UniversalEmbedder overview's generic “Gemma license” wording conflicts with that designation; the main model card additionally refers to a prohibited-use policy. Preserve these discrepancies for resolution against the exact shipped artifact's terms. Do not silently apply the original EmbeddingGemma license. Apache 2.0 permits redistribution subject to its notice/license obligations; include relevant notices and record modifications. [Google's Apache license text](https://ai.google.dev/gemma/apache_2).

The checked model file listings have no standalone `LICENSE`/`NOTICE` entry, so Apache card metadata is confirmed but a bundled artifact license file was not inspected. Runtime source/POM carries separate Apache notices; its third-party native/transitive notices need an inventory before distribution. Package a preserved publisher model card and explicit applicable license/notice materials, resolving inconsistent generic license wording before shipping. This research does not claim a legal approval of redistribution.

Recommended product strategy: explicit user-mediated import of a pinned `.litertlm` into app-private model storage, checksum/size/capability validation, atomic install, manifest with revision/runtime/dimension/prompt/preprocessing versions, and rollback. Bundling is an alternative after measuring final install size. No personal content is needed for setup. Cache files, audio and vectors have separate privacy/encryption policies. Never fetch remote samples or instantiate a runtime against a repository URL during inference. Strict offline acceptance means fresh installation plus model import with networking disabled, not merely a warm cached online demo.

## RAM/storage arithmetic: estimates, not benchmarks

Using rounded parameter counts, weights alone are approximately:

| Active configuration | FP32 | BF16 | Hypothetical uniform INT8 | Hypothetical uniform INT4 |
|---|---:|---:|---:|---:|
| Text 270M | 1.08 GB | 0.54 GB | 270 MB | 135 MB |
| Text+audio 570M | 2.28 GB | 1.14 GB | 570 MB | 285 MB |
| Full 740M | 2.96 GB | 1.48 GB | 740 MB | 370 MB |

Decimal bytes, excluding scales, metadata, tokenizer, activations, graph workspaces, mapped pages, copies, GPU allocations, Flutter and OS. Uniform quantization columns are arithmetic illustrations, **not available artifacts or supported accuracy claims**. Actual supplied mixed quantization and 484.6 MB file size supersede the uniform estimates for disk planning. Eight GB installed RAM does not establish process headroom. Measure PSS/RSS/native/GPU and system low-memory behavior; do not infer success from this table.

Float32 vector payload arithmetic: 10,000 vectors require 30.72 MB at 768d, 20.48 MB at 512d, or 10.24 MB at 256d before index/record overhead. Segmenting one recording into multiple vectors multiplies that count. Dimension reduction reduces search/storage cost, not encoder weight memory.

## Mandatory proof-of-concept and benchmarks after approval

The following are proposed experiment design and provisional decision gates, not measured performance or already-approved budgets.

1. **Compatibility/correctness:** lock runtime/artifact/hash and Android build; record phone model/SoC, OS/API, ABI, free storage, baseline RAM, battery health and build mode. Compare CPU reference and quantized output on identical preprocessed input. Verify finite vectors, correct norm/dimensions, prompt insertion exactly once, raw-audio embedding without ASR, and deterministic source/time-span mapping. Compare 768/512/256d retrieval; retain 128d only as an experiment because multimodal ranking may degrade. Test 5/10/30/120/300-second clips plus clips beyond the runtime context; do not silently truncate long voice memories.
2. **Corpus:** hold out at least 300 human-judged queries (100 Bangla, 100 English, 100 Banglish/code-switched) against 1,000 source memories, including at least 300 original recordings. Balance quiet/noisy speech, short/long recordings, colloquial phrasing, names/numbers, paraphrases, near-topic distractors, contradictions and irrelevant queries. Record consent and keep samples local. Keep development/tuning and test speakers/topics separate. Scale synthetic distractors to 10k and 50k records for index tests without confusing synthetic retrieval quality with real user quality.
3. **Text retrieval:** evaluate natural-language-to-text Recall@1/5/10, MRR@10 and nDCG@10 against keyword baseline, per language and script. Evaluate Bangla-script query to English memory and the reverse, Banglish spelling variants, negation and dates. Tune thresholds only on development data; report held-out confidence intervals and failures.
4. **Direct audio retrieval:** remove transcripts, transcript text, generated captions and content-bearing titles from indexing. Embed decoded original audio only; queries are independently written textual paraphrases. Score source-level and segment/time-span retrieval plus cross-language retrieval. Include semantically similar words with different meaning and sound-only distractors so speaker/noise classification cannot masquerade as thought retrieval.
5. **Related memories:** compare symmetric task embeddings with retrieval embeddings; manually label graded relatedness and relation types. Measure Precision@5, coverage, accept/dismiss behavior and duplicate rate. A high cosine value must not become a factual “supports” or “supersedes” edge. Suggested links remain reviewable and separate from user-authored links.
6. **Device performance:** physical Galaxy A52 4G 8 GB is mandatory; an emulator cannot certify it. Run release CPU/GPU trials, 2/4 CPU threads, text-only residency versus on-demand audio, batch size 1 versus small batches and short text signatures. At least 30 cold/warm query and indexing trials; record p50/p95/p99, startup/first query, audio real-time factor, model/index/cache sizes, PSS/RSS/native/GPU peaks, free RAM and LMK/restart events. Suggested initial goals: warm end-to-end query p95 <=1 second at 10k segments; 30-second audio indexing real-time factor <=1; incremental model PSS <=1 GB; native capture durable-save p95 remains <2 seconds and degrades <=10% under indexing. Negotiate based on baseline/device evidence rather than inventing pass results.
7. **Sustained effects:** randomize paired baseline/indexing runs at fixed brightness/connectivity, comparable battery charge and ambient temperature; 20–30-minute sustained corpus processing, at least three repeats. Record battery charge/energy where hardware exposes it, CPU utilization, thermal status/temperature, throttling, time-to-throttle and foreground frame timings. Proposed initial gate: no severe thermal status, no process kills or sustained capture jank; report energy per indexed audio minute instead of unsupported battery-life promises.
8. **Reliability/privacy:** airplane mode and local import; blocked DNS/socket instrumentation; missing/corrupt/mismatched model; low storage; cancellation; reboot/process death; simultaneous native save; source edit/delete during embedding; encrypted-vector storage decision; index rebuild/version swap and stale-job rejection. No capture entry point initializes model code. Verify deletion removes all source-derived vectors/links and interrupted indexing resumes without duplicate records.
9. **Staged image/video:** keep original media and timestamps; benchmark 70/140-token vision, keyframe sampling 0.2/1 fps and bounded overlapping segments. Test text-to-image, text-to-video moment and cross-modal related-memory retrieval; separately score events visible only in audio versus vision. Document whether exported runtime supports whole-video composition or requires application-managed keyframes/audio. Do not equate image embedding with temporal video understanding. These stages cannot replace required text+audio delivery.

If the first candidate fails: quantify failing latency/RAM/quality/energy and confidence bounds; try supported modality lazy loading, thread/batch caps, CPU/GPU selection, short signatures, bounded audio segments, charging-only backlog processing, cache lifecycle and documented alternate artifact/runtime combinations. Compare every change against multilingual retrieval quality. If no compatible configuration meets agreed budgets, stop with measurements and explicit alternatives for a product decision. EmbeddingGemma 2 and semantic memory remain required; substitution or scope reduction needs explicit approval.

## Separate offline ASR feasibility

Whisper supports multilingual transcription; its tokenizer includes Bengali `bn` and English `en`. That proves language labeling, not Bangla accuracy, Latin-script Banglish output or robust within-utterance code switching. Choose multilingual `tiny`/`base`/`small`, not `.en`; retain local editable transcripts as derived data. Whisper code/weights use MIT. [Official Whisper repository](https://github.com/openai/whisper), [language map](https://github.com/openai/whisper/blob/main/whisper/tokenizer.py).

`whisper.cpp` supports Android, CPU inference and integer quantization. Its published approximate tiny/base/small disk sizes are 75/142/466 MiB and memory 273/388/852 MB; these are general project figures, not simultaneous Cya!/embedding or A52 measurements. It is an initial native/JNI candidate with an Android example. [Maintainer repository](https://github.com/ggml-org/whisper.cpp).

`sherpa-onnx` offers local Android and Flutter/Dart integrations under Apache-2.0; its docs support non-streaming Whisper and ONNX exports, including CPU INT8 examples. Runtime license does not establish every model's license; pin exported model provenance and compare output against the original. Neither engine's platform support establishes Banglish quality. [Maintainer repository](https://github.com/k2-fsa/sherpa-onnx), [Whisper documentation](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/whisper/index.html).

ASR experiment: use the same held-out language/noise/speaker strata plus manually verified transcripts, at least 30 clips per language/noise cell. Report WER and Bangla CER, code-switch boundary accuracy, names/numbers preservation, dropped English/Bangla spans, hallucinations on silence/noise, real-time factor, cold/warm latency, RAM and energy. Publish raw-script and normalized scoring rules. Treat Banglish Latin transliteration as a separate output requirement; do not silently transliterate or translate. Compare multilingual tiny/base/small and one validated quantization each before adding larger models. Schedule ASR separately from embedding to avoid overlapping peak RAM; test user correction/provenance and cancellation. No ASR success is required to prove direct audio semantic retrieval, and ASR failure never authorizes a network API.
